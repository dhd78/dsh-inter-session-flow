# 可视化界面设计（v2 方向）

> 目标：从“打开就是画布”升级为“流程图库 → 流程图画布 → 运行”的产品结构。

## 一、整体信息架构

```text
入口
└─ 流程图库 / Flow Library
   ├─ 新建流程图
   ├─ 导入流程图包
   ├─ 最近打开
   ├─ 官方模板
   └─ 我的流程图
        └─ 流程图画布
           ├─ 节点模式
           ├─ 连线模式
           └─ 运行模式
```

插件打开后**先进入流程图库**，不再直接进入空白画布。

这样用户第一眼看到的是：

```text
我有哪些流程图
可以新建
可以导入
可以从官方模板开始
```

而不是：

```text
一张空画布，然后不知道该干什么
```

## 二、流程图库

### 布局

```text
┌──────────────────────────────────────────────┐
│  会话间流程 / Inter-session Flow              │
│  流程图库                                       │
│                                              │
│  [+ 新建流程图]  [导入流程图包]                   │
│                                              │
│  最近打开                                     │
│  ┌──────────────┐  ┌──────────────┐          │
│  │ 卡牌视频流程图  │  │ 研究报告流程图  │          │
│  │ v1.2.0       │  │ v0.9.0       │          │
│  │ 6 个工位      │  │ 4 个工位      │          │
│  │ 已绑定 / 未绑定│  │ 未绑定        │          │
│  └──────────────┘  └──────────────┘          │
│                                              │
│  官方模板                                     │
│  ┌──────────────┐  ┌──────────────┐          │
│  │ 并行调研      │  │ 内容审查      │          │
│  │ 汇总          │  │ 发布          │          │
│  └──────────────┘  └──────────────┘          │
└──────────────────────────────────────────────┘
```

### 每张流程图卡片显示

```text
名称
版本
工位数
Skill 依赖数
绑定状态
最近运行状态
最近打开时间
```

不要显示任何会话 id。

### 操作

```text
打开
复制为新流程图
导出
重命名
删除
查看运行记录
```

## 三、新建流程图

流程：

```text
新建
→ 输入名称 / 描述
→ 选择空白模板或官方模板
→ 创建流程图
→ 进入画布
```

第一版不必做复杂向导，只需要：

```text
名称
描述
初始模板（空白 / 官方模板）
```

## 四、导入流程图包

导入向导：

```text
1. 选择 .interflow.json
2. 校验包结构 / 版本 / 哈希
3. 展示流程图信息、工位数、Skill 依赖
4. 检查技能是否已安装
5. 检查插件/DSH 兼容性
6. 创建流程图
7. 进入画布
8. 提示“还有 N 个工位未绑定”
```

导入后可以进入画布，但运行前必须完成绑定和 preflight。

## 五、流程图画布

### 顶部栏

```text
← 流程图库    卡牌视频流程图 v1.2.0    [保存] [导出] [检查] [运行]
```

### 左侧栏

按模式变化：

#### 节点模式

```text
添加会话工位
官方工位模板
Skill 状态
```

#### 连线模式

```text
线类型：
  硬性输出线
  可回退输出线（预留）

边指令说明
```

#### 运行模式

```text
起始节点
运行输入
preflight 结果
运行 / 停止
运行状态
```

### 画布

节点卡片从“会话卡片”变成“工位卡片”：

```text
┌──────────────────────────┐
│ 文稿撰写                 │
│ sts-card-script 1.2.0    │
│ 会话：未绑定 / 写作助手   │
│                          │
│ ● IN1          OUT1 ●    │
└──────────────────────────┘
```

节点状态：

```text
未绑定
已绑定
缺 Skill
Skill 版本不符
离线
就绪
```

## 六、节点属性

节点属性分四个区：

### 工位身份

```text

描述
sessionPolicy
```

### Skill

```text
Skill 列表
版本
安装状态
必需 / 可选
权限/工具要求
```

### 本机绑定

```text
当前会话
绑定 / 解绑
会话状态
```

### 作业配置

```text
节点提示词
输出格式
默认输出口
输入口策略
输出口策略
```

### 调试

```text
预览最终提示词
试运行单节点
查看最近输出
```

## 七、边的语义

这里的边不是 AI 节点，而是**程序性的传送带**。

它负责：

```text
选择上游结果
按模板注入文本
决定投递到哪个输入口
决定线类型
```

它不负责：

```text
判断内容对错
自己调用 AI
自己重写结果
```

### 边指令

边可以填写：

```text
下面是上游结果：
{{input-x}}

请把它作为本工位的输入。
```

这是**静态文本注入**，不是 AI 决策。

### 边属性

```text
线类型：硬性输出线 / 可回退输出线（预留）
源输出口
目标输入口
边指令
目标字段：x / y / z（后续）
预览最终投递文本
```

### 边在画布上的显示

画布上显示中文类型名：

```text
硬性输出线
可回退输出线
```

选中后显示边指令摘要，而不是只显示一条无意义的线。

## 八、输出流模型

一条边代表一个输出流：

```text
某个输出口
→ 某条边
→ 某个输入口
```

边的程序性职责：

```text
选结果
替换 {{input-x}}
注入边指令
送入目标输入口
```

未来可扩展：

```text
字段选择
JSON 路径
条件分支
结果过滤
```

但这些必须保持**程序性、可预测**，不能偷偷调用 AI。

## 九、官方 Skill 工位

这是吸引用户的关键。

第一版建议提供 4 个官方工位：

### 1. 监管节点

```text
检查上游输出是否满足要求
决定：通过 / 退回 / 停止
```

需要 AI 能力；应作为官方 Skill 模板。

### 2. 校验节点

```text
格式校验
字段校验
JSON schema 校验
规则检查
```

优先做确定性校验，必要时再接 AI。

### 3. 汇总节点

```text
多路输入合并
生成统一汇总
```

可以是 AI 工位，也可以是程序性 merge。

### 4. 人工确认节点

```text
运行到此处暂停
等待人确认
继续 / 停止 / 修改
```

这是流程图里非常实用的官方节点。

### 后续官方工位

```text
输入节点
输出节点
路由节点
分发节点
重试节点
评审节点
发布节点
```

官方 Skill 工位要配：

```text
图标
说明
输入输出
示例
版本
文档
```

## 十、运行模式

运行模式保留现有内容，但增加：

```text
Preflight 结果
工位绑定状态
Skill 状态
运行快照
运行事件
节点输出
停止
单节点重试
```

有阻断项时：

```text
[运行] 按钮禁用
列出：
  2 个工位未绑定
  1 个 Skill 缺失
  1 条边 target 非法
```

## 十一、视觉风格

- 流程图库：卡片式，信息优先；
- 画布：工位卡片 + 中文线名 + 状态徽章；
- 禁用项：灰显并给原因；
- 缺 Skill：黄色警告；
- 未绑定：中性提示；
- 错误：红色，但不要清空画布；
- 运行中：节点呼吸/进度状态；
- 保持现有六套配色和中文 / English 切换。

## 十二、页面状态

```text
library       流程图库
canvas        画布
import        导入向导
preflight     检查结果
run           运行模式
```

画布内部仍有：

```text
nodeMode
wireMode
runMode
```

## 十三、第一版实现范围

```text
流程图库
新建 / 导入 / 打开 / 导出
工位卡片
Skill 引用
节点属性
边指令
preflight
运行模式
```

暂不做：

```text
官方 Skill 市场
在线模板下载
复杂动画
多人协作
远程执行
```

## 十四、产品判断

如果用户打开插件看到的是“空画布”，他需要自己理解一切。

如果看到的是：

```text
官方模板
我的流程图
导入流程图包
```

他会更快理解：

> 这是一个可以复制、可以运行的流程图工具。

流程图库不是装饰，它是产品定位的第一屏。
